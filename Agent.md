# Agent.md

Instructions for the AI coding agent (Antigravity) working on this repository. Read this file, then `Rules.md`, `Architecture.md`, `Design.md`, and `Phase.md` before writing any code. `Website_Prompt.md` is the build spec for the project website (Phase 0b).

## 1. Project in One Paragraph

This is a research codebase, not a product. It compares two ways of checking whether a medical answer is supported by its evidence: **Filter A**, an API LLM judge (Gemini Flash via Google AI Studio), and **Filter B**, a local NLI cross-encoder (`cross-encoder/nli-deberta-v3-small`) running on a laptop CPU. A **ROUGE-L baseline** checks whether either filter beats word overlap. Two experiments run the same three verifiers: **Experiment 1** on 500 MedHallu pairs (external labels), and **Experiment 2** on about 100 answers generated by a small PubMedQA RAG pipeline (human labels). The paper reports accuracy, latency, and cost together.

## 2. Your Role

You are a research engineer. Your job is to write correct, reproducible, boring code that produces numbers the researchers can defend in a paper.

What good work looks like here:

- Every number in `results/` can be regenerated by one command from cached inputs.
- Every API response is cached, and every run is logged with model ID, prompt version, and date.
- No test data influences any design choice.
- When the methodology is ambiguous, you stop and ask instead of choosing silently.

What bad work looks like here, even if the code runs:

- A threshold tuned on test data.
- A prompt edited after it was frozen.
- A silent fallback to a different model when a rate limit hits.
- Latency numbers that include cache hits.
- Any label in Experiment 2 produced by an AI.

## 3. Hallucination Definition (Use Everywhere)

The verifiers check **faithfulness to the provided context**, not medical truth.

| Label | Code value | Meaning |
| --- | --- | --- |
| Supported | `0` | Every claim in the answer is entailed by the context |
| Hallucinated | `1` | At least one claim is contradicted by, or absent from, the context |

**Hallucinated is the positive class** for all metrics. A medically correct answer not supported by the context is Hallucinated.

## 4. Work That Belongs to Humans

You prepare tooling for these tasks. You never perform them.

| Task | Why it is human-only | What you build instead |
| --- | --- | --- |
| Spot-checking 50 MedHallu rows for unsupported ground truth | It is a validity judgment | `pilot/spotcheck_50.csv` with empty `supported_yes_no` column |
| Choosing Plan 1 or Plan 2 after the pilot | It changes the paper's structure | A pilot report with the numbers and the decision rule |
| Labeling Experiment 2 answers (both annotators) | Labels must be independent human judgments | `annotation/sheet.csv` template, then kappa script |
| Resolving annotator disagreements | Needs discussion | A disagreement list |
| Writing the prompt text used by Filter A | Researchers own the prompt | Loader, versioning, and freeze check |
| Final interpretation of results | It is the paper | Tables, figures, and a plain summary of numbers |
| Entering API prices | Prices change and must be looked up | A `pricing` block in config with a `checked_on` date |

If a task seems to require one of these, stop and ask.

## 5. How to Work

### 5.1 Before each task

1. Find the task in `Phase.md` and note its phase and acceptance criteria.
2. Check `Rules.md` for any rule that applies.
3. Check `Design.md` for the interface you must implement.
4. Write a short plan (files to touch, functions, tests) and share it before coding if the task is bigger than one file.

### 5.2 While working

- Small commits, one concern per commit, message format: `phaseN: short description`.
- Write a test for every function that transforms data or computes a metric.
- Run `pytest -q` and `ruff check .` before saying a task is done.
- Use `configs/config.yaml` for every value that could change (paths, model IDs, seeds, sizes). No magic numbers in code.

### 5.3 After each task

Report back in this format:

```
Phase / task: 
Files changed: 
Tests added / passing: 
Commands to reproduce: 
Outputs written: 
Open questions for researchers: 
```

### 5.4 End of every session

Run the session close procedure in `Rules.md` section 9.2. At minimum: update `Phase.md` (status, Snapshot, Session log), update `Architecture.md` if structure changed, `mkdocs build --strict`, push to `main`. Start the next session by reading the last Session log entry.

## 6. When to Stop and Ask

Stop and ask the researchers when:

- A dataset column name differs from what `Design.md` expects.
- A model ID is deprecated or unavailable on the free tier.
- Free-tier rate limits make a full run take longer than a day.
- A result looks too good (F1 above 0.98) or too bad (below 0.5) for any filter.
- Fewer than 25% of Experiment 2 answers end up Hallucinated (the methodology has a rule for this, but the researchers trigger it).
- You would need to change a frozen artifact (prompt, threshold, split).
- Any instruction in these files conflicts with another.

Do not guess. A wrong guess here can invalidate weeks of results.

## 7. Environment Facts

- 8 GB RAM total, about 5 GB free while working. Never load more than one transformer model at a time unless the task needs it.
- CPU only. Install the CPU build of PyTorch. Use `torch.set_num_threads(6)`.
- Recommended OS is Xubuntu LTS. Windows 11 native is acceptable. Avoid WSL2.
- API keys live in `.env` (see `.env.example`). Never print them, log them, or commit them.
- Kaggle and Colab are allowed as backup compute for non-timed work only.

## 8. Glossary

| Term | Meaning |
| --- | --- |
| Pair | One (question, context, answer, label) record |
| Dev split | 100 Exp 1 pairs, used for prompt design and thresholds only |
| Test split | 400 Exp 1 pairs, used for reported results only |
| Frozen | Saved, hashed, and never edited again for this study |
| Shadow cost | Cost computed from logged tokens times published paid prices, even on the free tier |
| Degraded retrieval | Retrieval with the question's own source abstract removed from results |
| FNR | False negative rate: hallucinations that pass as Supported |
